## 2024-05-20 - [CRITICAL] Missing Authorization Check in Topic Routes
**Vulnerability:** The endpoints in `src/router/topic.routes.ts` (`/cet`, `/all`, `/subject/:subjectName`) were entirely unauthenticated, allowing any user (including unauthenticated ones) to access topic-related data. The `authMiddleware` was imported but never actively applied to the router's middleware chain.
**Learning:** Even if authentication middleware is imported, it must be explicitly applied using `router.use(authMiddleware)` or added to individual route definitions. A missing application of middleware can silently expose endpoints.
**Prevention:** Always verify that imported security middlewares are actually invoked in the router chain. Implement automated checks or tests to ensure all protected routes enforce authentication.
## 2026-03-04 - [MEDIUM/HIGH] Missing input length limits on Pagination and Test Configuration (DoS risk)
**Vulnerability:** The application was missing input length limits on the pagination `limit` parameter in `admin.controller.ts` and `testHistory.controller.ts`, as well as on `numberOfQuestions` in `testSchema.ts`. A malicious user could request extremely large values (e.g., `limit=1000000`), leading to massive database queries and memory exhaustion (Denial of Service).
**Learning:** Even when inputs are typed correctly (e.g., as integers), their logical boundaries must be strictly enforced. Unbounded inputs that dictate resource allocation (like query size, array length, or time loops) are prime vectors for DoS.
**Prevention:** Always enforce upper bounds (maximum values) on any user-provided parameter that dictates the amount of data processed or retrieved, using techniques like `Math.min(input, MAX_ALLOWED)` or Zod's `.max()` constraint.

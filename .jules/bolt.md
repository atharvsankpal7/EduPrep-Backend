## 2024-05-24 - [Avoid O(N^2) Lookup in Arrays]
**Learning:** Found a performance bottleneck where `Array.prototype.find()` was used inside an `Array.prototype.map()` loop over identical sized arrays (`testQuestionInfo` and `selectedAnswers`), causing an `O(N^2)` time complexity for data lookup. This can significantly slow down API endpoints as the size of `N` increases (e.g., tests with many questions).
**Action:** When correlating data across two arrays, convert the lookup array into a `Map` prior to iteration to achieve `O(1)` access time, transforming the overall complexity to `O(N)`. I refactored `submitTest` in `src/controllers/testResult.controller.ts` to implement this pattern.
## 2025-03-05 - Avoid Redundant DB Lookups and Refactoring Hygiene
**Learning:** In controllers, fetching an entity immediately after it was created or validated by middleware (e.g. `req.loggedInUser` or right after `createUser`) via a separate database query (like `findUserByIdPublic`) is an anti-pattern. Mapped properties from the newly-created or middleware-provided object should be used instead. Additionally, concurrent operations like session revocation and token clearing should be parallelized. I also learned that creating temporary utility scripts (`patch_*.ts`) that get left in the project root is a severe codebase hygiene violation.
**Action:** Always map objects directly from the source if the data is already present to avoid redundant database calls. Parallelize asynchronous side-effects where possible. Never commit temporary tool scripts to the repository—use inline sed/awk commands or ensure `replace_with_git_merge_diff` is used carefully, or delete temporary scripts immediately after they run.
